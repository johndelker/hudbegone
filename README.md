# HUD Begone

Open the configuration window with `/hudbegone`. Controls use Show checkboxes: checked leaves the element available to the game, unchecked hides it. Player Frames contains solo HP/MP/TP and status effects; Party Frames contains party, alliance and target frames; Chat Frames contains compass, chat channel visibility, Chat Background Opacity and Chat Text Opacity. Background opacity ranges from 0 (fully transparent) to 1 (fully opaque), with text controlled separately. Existing saved background appearance is preserved using the legacy inverse transparency value. Existing saved visibility choices are preserved. Turning Show back on or unloading restores captured flags for matching live objects.

Chat Text Opacity ranges from 0 (invisible messages) to 1 (maximum opacity through the font's glyph mask). It defaults to 127/255, approximately 0.50. Chat glyphs use standard source-alpha blending. The high-resolution font stores covered pixels at alpha 128; the hook compensates for that encoding so the maximum setting reaches full opacity. The standard font already reaches alpha 255 and keeps ordinary alpha modulation. Font selection is checked on each glyph draw, so changing the game's font setting does not require reloading the addon. Higher opacity covers more of the background without increasing the text's RGB values, including inline colors. Both chat windows use the shared message renderer; opacity covers their normal and scrolling-message paths. Background opacity matches both chat-window owners and excludes the separate title strip. The hook applies only inside a native chat-message draw; other text, chat backgrounds and the channel graphic retain their own rendering. The previous device blend states, texture-alpha operation and native glyph colors are restored after submission. If the device or saved-state queries are unavailable, that draw uses the native renderer. Values save in hudbegone.ini; unloading restores the original renderer calls. If either validated renderer signature is unavailable or already hooked, only this control is unavailable. Zero skips message drawing. Actual appearance and font-mask coverage require an in-game check.

Load with `/addon load hudbegone`. Replace any startup `/addon load hidecompass` with this new name. Unload hidecompass and hideparty before using hudbegone so two addons do not fight over the same HUD elements. hudbegone does not hide Ashita's custom addon overlays and does not replace hideui.

Settings save in hudbegone.ini. On first use, if that file is absent, the prior hidecompass.ini compass setting is imported. Other hiding options default to off. bettertarget supplies the configurable replacement cursor when you hide the native target window.

Commands: `/hudbegone compass|party|alliance|target|solo|status|channel hide|show|toggle`; `/hudbegone help`.

Other toggles remain functional if an individual signature cannot be located; unsupported controls are identified in the menu.

Unchecking Show Solo Player Frame hides the native combat HP/MP/TP display when it exists. Its pointer is checked every frame, so entering or leaving combat is handled automatically. Unchecking Show Status Effects hides the native icon display while active effects remain unchanged. Both Show options default to checked and save separately. Resource names and ownership are verified before visibility writes; unsupported client signatures disable only the affected control. Original visibility bytes are restored for the matching live window when disabling a control or unloading. Actual game behavior still requires in-game testing, including combat transitions and zoning.

HUD visibility code derives from Ashita's hideparty addon and is GPLv3-or-later; see hud.lua and LICENSE-GPLv3.md. Requires Ashita common/imgui. Game memory signatures and restored HUD behavior require in-game verification.

Visibility updates run at `d3d_beginscene` before each scene starts; the configuration window remains at `d3d_present`. Solo windows created when entering combat are additionally suppressed inside the native primitive draw routine, after their native update and before rendering. This guard follows the current owner slot and verifies both ownership and the gaugewin resource, covering creation after BeginScene without changing status or other HUD drawing. It leaves native visibility flags intact for the existing capture/restore logic and detaches when both Show Solo Player Frame and Show Target Window are checked, or when the addon unloads. If the renderer signatures are absent, ambiguous, or already patched, the ordinary visibility flags remain the fallback and combat-entry flashing may persist. Actual flash elimination still needs an in-game check. Existing hide/show/toggle command meanings and internal hide keys are unchanged.


Show Target Window also uses the native draw guard. When unchecked, the matching targetwi primitive is skipped before rendering, including a target frame created after the scene-start visibility pass. Solo and target suppression share one hook and can be enabled independently. The guard detaches when both windows are shown or the addon unloads. Target cursor anchor updates remain in the game native window update; visibility flags are still captured/restored by the existing code. If the draw guard is unavailable, target hiding falls back to visibility flags and a brief flash may remain.
